インフラの案件では、作る時間と同じくらい、書く時間があります。設計を決めたら設計書に、設定する値はパラメータシートに、作業は手順書に書き、ほかの人の確認を受けてから手を動かします。参画して最初に任される仕事が、こうした文書の作成や更新であることも、珍しくありません。

この付録には、ひな形と、第2部で作った構成での記入例を載せます。記入例の値は、{{ch:s7}}の参考実装と同じです。会社や案件ごとに書式は違いますが、書く内容は共通しています。案件に書式があれば、そちらに従ってください。

## 文書の種類と、書く時期

{{fig:docflow|文書を書く順番と、見直しの流れ}}

| 文書 | 書くこと | 書く時期 | この本で書く章 |
|---|---|---|---|
| 要件定義書 | 何を、どの水準で実現するか。非機能要件を数字で書く | 設計の前 | {{ch:req}} |
| 基本設計書 | 構成と、その構成を選んだ理由 | 構築の前 | {{ch:req}}から{{ch:review}}、{{ch:cap}} |
| パラメータシート（詳細設計書） | 資源ごとの、設定する値 | 構築の前。構築の後に、実際の値と突き合わせる | {{ch:s2}}から{{ch:s4}} |
| 作業手順書 | 作業の順番、1手順ごとの期待する結果、切り戻しの方法 | 作業の前。確認を受けてから実施する | {{ch:s5}} |
| 試験項目書 | 何を確かめれば「できた」と言えるか。結果と証跡 | 構築の前に項目を決め、構築の後に結果を書く | {{ch:s3}}、{{ch:s4}} |
| 運用手順書 | 定常の作業と、異常のときの最初の動き | 運用を始める前 | {{ch:s5}}、{{ch:sre}} |
| 障害報告書 | 何が起き、どう対応し、どう防ぐか | 障害の後 | {{ch:s5}} |

IaCを使う案件では、パラメータシートの役割の一部を、コードが担います。それでも、「なぜその値にしたか」と「環境ごとに違う値の一覧」は、文書として求められることがあります。コードと文書の両方がある場合は、どちらを正とするかを、先に決めておきます。

## 書くときの決まり

- 値には、理由を添える。「10.0.0.0/16」だけでなく、「社内のネットワークと重ならない範囲として割り当てを受けた」のように書く
- 設定した人と、確認した人を分ける。確認した人の名前と日付を残す
- 版と、改訂の履歴を付ける。いつ、誰が、何を、なぜ変えたかを書く
- 秘密の値を書かない。パスワード、アクセスキー、秘密鍵は書かず、保管場所（Secrets Manager のシークレットの名前など）を書く
- 実際の設定と突き合わせる。構築の後、コマンドの出力や画面と見比べる。違いがあれば、どちらが正しいかを決めて、直す
- 既定値のままにした項目も、動作に関わるものは書く。「指定しなかった」ことと「既定値を選んだ」ことは、後から見ると区別がつかない（{{ch:ts}}のシナリオ10）

## パラメータシートの記入例

第2部で作った構成のパラメータシートです。項目、値、理由の3つを書きます。自分で作った構成について、同じ形で書いてください。

### 共通

| 項目 | 値 | 理由 |
|---|---|---|
| リージョン | ap-northeast-1（東京） | 利用者が国内にいるため |
| 名前の付け方 | cloudbook-lab-役割（例：cloudbook-lab-alb） | システムの名前、環境、役割がわかるようにする |
| すべての資源に付けるタグ | Project=cloudbook、Env=lab、ManagedBy=terraform | 費用の内訳と、消し忘れの確認に使う |

### ネットワーク

| 項目 | 値 | 理由 |
|---|---|---|
| VPCのCIDR | 10.0.0.0/16 | 学習用。本番では、ほかのネットワークと重ならない範囲の割り当てを受ける |
| DNSによる名前解決、DNSホスト名 | 有効 | エンドポイントをDNS名で指定するため |
| NATゲートウェイ | 1台。public-a に置く | 学習用のため1台。本番ではAZごとに置く |

| サブネット | AZ | CIDR | ルートテーブル |
|---|---|---|---|
| public-a | 1つ目のAZ | 10.0.0.0/24 | public |
| public-c | 2つ目のAZ | 10.0.1.0/24 | public |
| app-a | 1つ目のAZ | 10.0.10.0/24 | app |
| app-c | 2つ目のAZ | 10.0.11.0/24 | app |
| db-a | 1つ目のAZ | 10.0.20.0/24 | db |
| db-c | 2つ目のAZ | 10.0.21.0/24 | db |

| ルートテーブル | 宛先 | 送り先 | 理由 |
|---|---|---|---|
| public | 0.0.0.0/0 | インターネットゲートウェイ | ALBとNATゲートウェイを置くため |
| app | 0.0.0.0/0 | NATゲートウェイ | ソフトウェアの取得と、Systems Manager への通信のため |
| db | なし（VPCの中だけ） | なし | データベースを、外部と直接通信させないため |

### セキュリティグループ

| グループ | 向き | プロトコルとポート | 相手 | 理由 |
|---|---|---|---|---|
| alb | 受信 | TCP 80 | 0.0.0.0/0 | 利用者からのHTTP。学習用。本番ではHTTPS（443）にする |
| alb | 送信 | TCP 80 | app のセキュリティグループ | 振り分けと、ヘルスチェック |
| app | 受信 | TCP 80 | alb のセキュリティグループ | ALBからだけ受け付ける。22番（SSH）は開けない |
| app | 送信 | すべて | 0.0.0.0/0 | ソフトウェアの取得、Systems Manager、データベースへの通信 |
| db | 受信 | TCP 5432 | app のセキュリティグループ | アプリサーバーからだけ受け付ける |
| db | 送信 | なし | なし | データベースから通信を始める必要がない |

### サーバーと負荷分散

| 項目 | 値 | 理由 |
|---|---|---|
| OSのイメージ | Amazon Linux 2023（x86_64）の最新 | 起動テンプレートを作る時点の最新を使う |
| インスタンスタイプ | t3.micro | 学習用。本番では、負荷の測定にもとづいて決める |
| サーバーの中から認証情報を取り出す経路（IMDS） | v2だけを許可 | 古い方式を悪用した、認証情報の持ち出しを防ぐ |
| サーバーのロール | cloudbook-lab-app。AmazonSSMManagedInstanceCore と、データベースの接続情報の読み取りだけ | 必要な権限だけを付ける |
| 台数 | 最小2、最大4 | 1つのAZが止まっても、応答を続けるため |
| 配置するサブネット | app-a、app-c | 2つのAZに分ける |
| Auto Scalingのヘルスチェック | ELB。猶予期間120秒 | ALBが異常と判断したサーバーを入れ替える。起動に1分ほどかかるため、余裕を持たせる |
| サーバーの入れ替え方 | 半分ずつ（正常な割合の下限50%） | 入れ替えの間も、応答を続けるため |
| ALBの種類と配置 | インターネット向け。public-a、public-c | 利用者からの入口 |
| リスナー | HTTP 80 → ターゲットグループへ転送 | 学習用。本番では、証明書を付けてHTTPSで受ける |
| ターゲットグループ | HTTP 80 | Webサーバーが待ち受けるポートに合わせる |
| ALBのヘルスチェック | パス /、成功コード200、間隔15秒、タイムアウト5秒、しきい値は正常2回・異常2回 | 異常を30秒ほどで検知する |
| 登録解除の待ち時間 | 30秒 | 処理中の依頼が終わるのを待つ。学習用に短くしている |

### データベース

| 項目 | 値 | 理由 |
|---|---|---|
| 識別子 | cloudbook-lab-db | 名前の付け方に従う |
| エンジンと版 | PostgreSQL 17 | 作成する時点で、十分にサポート期間が残っている版を選ぶ |
| インスタンスクラス | db.t4g.micro | 学習用 |
| 保存領域 | gp3、20GB、暗号化あり | 暗号化は、後から有効にできないため、最初から有効にする |
| データベース名、管理者の名前 | appdb、postgres | |
| 管理者のパスワード | Secrets Manager が生成して保管する。値は、どの文書にも書かない | パスワードを、人もコードも知らずに済むようにする |
| 配置するサブネット | db-a、db-c | 外部への経路がないサブネットに置く |
| パブリックアクセス | なし | |
| マルチAZ | なし | 学習用。本番では有効にする |
| 自動バックアップの保持 | 1日 | 学習用。本番では、要件の目標復旧時点から決める |
| 削除保護、削除時の最終スナップショット | なし、取らない | 学習用。何度も作り直すため。本番では、どちらも逆にする |

:::tip 値を、実際の設定と突き合わせる
各ステップの「実技の合格基準」のコマンドは、パラメータシートの値を確かめるためにも使えます。シートの1行ごとに、実際の値を表示するコマンドを言えるようにしてください。「シートにそう書いてある」ではなく、「実際にそうなっている」ことを示すのが、構築の完了です。
:::

## 作業手順書のひな形

作業手順書は、「書いた人でなくても、同じ結果になるように実行できる」ことを目標に書きます。操作だけでなく、1手順ごとの期待する結果と、うまくいかなかったときの戻し方を書きます。

```text
作業手順書

作業の名前  ：
目的        ：
対象        ：（アカウント、環境、資源の名前）
日時        ：（開始と、終了の予定）
作業する人  ：            確認する人：
利用者への影響：（影響の有無。ある場合は、内容と時間）

事前の確認（1つでも満たさなければ、作業を始めない）
  1.
  2.

手順
  番号 | 操作（コマンドや画面） | 期待する結果 | 実際の結果 | 時刻

切り戻し
  戻すと判断する条件：
  戻す手順          ：
  戻した後の確認    ：

事後の確認
  1.
  2.

連絡先（異常のときに、誰へ、どの手段で連絡するか）：
```

### 記入例：アプリサーバーの入れ替え

OSの更新を反映するために、動いているサーバーを新しいサーバーへ入れ替える作業の例です。{{ch:s5}}の運用の演習で使います。

| 欄 | 記入例 |
|---|---|
| 作業の名前 | アプリサーバーの入れ替え |
| 目的 | OSの更新を反映した、新しいサーバーに入れ替える |
| 対象 | 学習用アカウント、lab 環境、Auto Scalingグループ cloudbook-lab-app |
| 利用者への影響 | なし（半分ずつ入れ替えるため）。作業の間、応答を監視して確かめる |
| 事前の確認 | ターゲットが2台とも healthy である。作動中のアラームがない。ほかの変更作業と重なっていない |
| 戻すと判断する条件 | 200以外の応答が続く。新しいサーバーが、5分たっても healthy にならない |
| 戻す手順 | 入れ替えを中止する。新しいサーバーに問題がある場合は、起動テンプレートを前の版に戻して、もう一度入れ替える |

| 番号 | 操作 | 期待する結果 |
|---|---|---|
| 1 | 別のターミナルで、ALBのURLを1秒ごとに開き続ける | 200が表示され続ける |
| 2 | 今のサーバーのIDを記録する | 2台のIDが表示される |
| 3 | 入れ替えを始める | 入れ替えのIDが表示される |
| 4 | 進み具合を、1分ごとに確かめる | 状態が InProgress から Successful になり、割合が100になる |
| 5 | サーバーのIDを、もう一度表示する | 2台とも、2で記録したIDと違う |
| 6 | ターゲットの状態を確かめる | 2台とも healthy |
| 7 | 1のターミナルの表示を確かめて、止める | 作業の間、200以外がない |

新しいイメージが公開されている日は、{{ch:s7}}のコードで `terraform apply` を実行すると、起動テンプレートの更新と、この入れ替えが、一度に進みます。その場合も、事前の確認、作業中の監視、事後の確認は同じです。

## 試験項目書のひな形

試験項目書は、「何を確かめれば、できたと言えるか」を、作る前に決めておく文書です。正常に動くことだけでなく、壊れたときの動きと、許可していない通信が通らないことも、項目にします。

| 番号 | 分類 | 確かめること | 手順 | 期待する結果 | 結果 | 証跡 |
|---|---|---|---|---|---|---|
| 1 | 正常 | 利用者がページを開ける | ALBのURLを開く | 200が返り、ホスト名が表示される | | 画面 |
| 2 | 正常 | 2台に振り分けられる | ALBのURLを10回開く | ホスト名が2種類以上表示される | | コマンドの出力 |
| 3 | 障害 | 1台が止まっても、応答が続く | 1台を終了させ、ALBのURLを開き続ける | 200が返り続ける。数分後に、2台に戻る | | 出力と、Auto Scalingの履歴 |
| 4 | 障害 | Webサーバーが止まったサーバーは、入れ替えられる | 1台でWebサーバーを止める | そのサーバーが unhealthy になり、新しいサーバーに入れ替わる | | Auto Scalingの履歴 |
| 5 | セキュリティ | サーバーに、SSHで入れない | アプリ用のセキュリティグループの受信ルールを表示する | 22番の許可がない | | コマンドの出力 |
| 6 | セキュリティ | データベースに、外から届かない | 手元の端末から、エンドポイントの5432番に接続を試みる | 接続できない | | コマンドの出力 |
| 7 | セキュリティ | データベースは、アプリサーバーからだけ届く | アプリサーバーから接続する | 接続できる | | 画面 |
| 8 | 運用 | バックアップから戻せる | スナップショットから、別の名前で復元する | 復元したデータベースで、登録済みのデータを読める | | 画面と、かかった時間 |

「結果」には、合格・不合格だけでなく、実施した日と人を書きます。「証跡」は、後から第三者が確かめられるものにします。画面の写しには、時刻と、対象の名前が写るようにします。
