## 手元でページを作る

Python 3.12と、回帰チェック用のNode.js 22以降を使います。

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --require-hashes -r requirements.txt
node --test tests/*.test.cjs
python -m unittest discover -s tests -p 'test_*.py'
python tools/build.py --strict
python tools/check_site.py
python -m http.server 8000 --directory dist
```

`dist/index.html` と `dist/assets/` ができます。ブラウザーで `http://localhost:8000/` を開いて確認します。公開時も `dist/` 全体が必要です。CSPと同一オリジンの資源を確認するため、`file://` での直接表示は使いません。

`--artifact` は任意のHTML断片も出力します。同じ `assets/` が必要で、単一ファイルとして貼り付ける形式ではありません。

## 原稿の書き方

ふつうのMarkdownに、次の書き方を加えています。

| 書き方 | 意味 |
|---|---|
| `:::goal` 〜 `:::` | 囲み。`goal`（この章のゴール）、`note`（要点）、`tip`（現場のコツ）、`warn`（注意）、`pit`（落とし穴）、`lab`（わざと壊してみる）、`ref`（公式資料で確かめる）、`sum`（この章のまとめ）、`req`（要件）、`think`（考えどころ）、`dir`（構成の方向性）。種類の後ろに、題を書ける |
| `:::q 種別 \| 題` 〜 `:::` | 設問。途中に `:::hint` を置くとヒント、`:::a` を置くと、そこから下が解答（折りたたみ）になる。閉じる `:::` は、最後に1つ |
| `{{ch:key}}` | 章への参照。「第21章」のように表示される。`{{ch:key\|t}}` で、題名も付く |
| `{{fig:name\|説明}}` | 図。`name` は `tools/figs.py` の関数の名前 |
| `- [ ] 項目` | チェックリスト |
| `## 見出し` | 節。番号は自動で付く |

章を追加するときは、`book/` にファイルを置き、`tools/manifest.py` に1行を加えます。ファイル名は `番号-key.md` の形で、`key` の部分が `manifest.py` の `key` と一致している必要があります。

## 公開の仕組み

1. 作業ブランチからPRを作る。`Build and security checks` が成功し、差分を確認してから `main` にマージする。
2. Actionsの **Verify and publish** を開き、`main` を選んで **Run workflow** を実行する。
3. 検証に成功すると `github-pages` 環境の承認待ちになる。対象のコミットと差分を確認し、所有者が承認する。
4. 公式のPagesアクションが成果物を公開する。公開URLと実行結果を確認する。

PRや通常のpushだけでは公開しません。`main` はPRと成功した検証を必須にし、強制pushと削除を禁止します。1人運用でも確認工程を飛ばさないため、公開環境の承認は所有者自身でも行える設定です。これは別の人による独立レビューを保証するものではありません。共同運用では、別のレビュアーによるPR承認や、自己承認を禁止した公開承認を追加してください。

公開元はGitHub Actionsです。生成物を `gh-pages` へ強制pushする方式は使いません。ビルドは `contents: read` だけ、公開ジョブだけが `pages: write` と `id-token: write` を持ちます。外部アクションは完全なコミットID、Python依存は版と配布ファイルのSHA-256で固定し、Dependabotの更新PRで差分を確認します。

## プライバシーと安全性

フォントは端末内のものを使い、第三者のフォント配信や解析サービスを読み込みません。読了・チェックリスト・表示設定はブラウザー内に保存します。不正な保存値は無視し、認証情報を保存する機能はありません。CSPで同じサイト内のJavaScript・CSSだけを許可し、HTML内への実行コードの埋め込みを禁止しています。GitHub Pagesの配信自体にはGitHubのサービス規約・プライバシーポリシーが適用されます。

保護設定と検証の範囲は [SECURITY.md](SECURITY.md)、利用許諾の状態は [LICENSE.md](LICENSE.md) を参照してください。
