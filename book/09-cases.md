:::tip 事例を読むときの3つの視点

## 企業がクラウドを選ぶ理由

事例を整理すると、移行のきっかけと狙いは次の6つに集約されます。

| きっかけ・狙い | 内容 | 該当する事例 |
|---|---|---|
| ハードウェアの老朽化・保守切れ | 数年ごとの機器更新をやめたい | 日本食研、日本ペイント |
| コスト削減 | 機器・データセンター・運用の費用を下げる | ミニストップ、明治、三菱商事 |
| 開発スピード | 新サービスや改修を速く出したい | ミスミ |
| 災害対策（BCP） | 東京・大阪など複数リージョンで止まらない仕組みを作る | 三菱商事、日本ペイント |
| データ活用 | 散らばったデータを集め、高速に分析する | アスタミューゼ、リクルートライフスタイル |
| 先端技術の利用 | AI・機械学習などをすぐ試せる | ミニストップ |

## クラウドが向かないこともある

クラウドは万能ではありません。次のような場合は、オンプレミスのほうが合理的なこともあります。

- 24時間365日、高い負荷が一定で、何年も構成が変わらないシステム（従量課金の利点が出にくい）
- 法規制や契約で、データを外部事業者に預けられないシステム
- 工場の制御など、ミリ秒単位の応答が必要で現場から離せないシステム
- 特殊なハードウェアや古いOSに依存し、移行コストが効果を上回るシステム

移行するかどうかは、技術の新しさではなく「何を解決したいか」で判断するのが基本です。

## 事例から自分の案件を考える

事例は、そのまま真似るためではなく、自分の案件の判断材料として読みます。事例のきっかけと自分の案件の課題が同じなら、方式と効果は参考になります。違うなら、同じ方式を選ぶ理由はありません。

たとえば「機器の保守切れ」がきっかけの案件では、期限までに確実に移すことが最優先で、作り直しよりも、変更の少ない移行が選ばれやすくなります。一方、「開発の速さ」が狙いの案件では、そのまま移すだけでは目的を達成できず、構成や開発の進め方の見直しまで踏み込む必要があります。目的によって、選ぶべき方式も、成功の測り方も変わります。

:::sum
- 国内の事例は、基幹システムの移行、メインフレームからの脱却、データ分析基盤の構築が代表的
- 移行のきっかけは、保守切れ、コスト、開発の速さ、災害対策、データ活用、先端技術の6つに整理できる
- 公表された効果は、実績か目標か、何の費用かを確認して読む
- クラウドは万能ではない。「何を解決したいか」から判断する
:::

## 章末問題

:::q 読み取り | 効果の数字を比べる
本文の表に「維持・運用コストの80%削減を想定（2024年3月発表時点の想定）」と「移行後の最適化でAWS利用料を15.9%削減（2024年公表）」という2つの記述があります。この2つを単純に「80%のほうが効果が大きい」と比べてはいけない理由を、2つ以上挙げてください。
:::a
解答例：

1. 想定と実績の違い：前者は発表時点の見込みで、後者は実際に得られた結果
2. 対象の違い：前者はシステム全体の維持・運用コスト、後者はAWSの利用料。母数が違う
3. 比較の起点の違い：前者はメインフレームからの移行の前後、後者はクラウドに移した後の最適化の前後。出発点の費用水準がまったく違う

数字を顧客への説明や提案に使うときは、この3点（実績か、何の費用か、何と比べてか）を必ず確認し、出典と時点を添えます。
:::

:::q 判断 | 移行に向くか
次の4つのシステムについて、クラウドへの移行に向くかどうかを、理由とともに答えてください。

1. 5年前に導入したサーバーの保守が来年切れる、社内の文書管理システム
2. 24時間ほぼ一定の負荷で動き、今後10年は仕様が変わらない見込みの計測データ収集システム
3. 契約で、データを自社の施設の外に出せないと定められている受託システム
4. 月末と期末にだけ処理が集中する、経費精算システム
:::a
1. 向く。機器を更新する代わりに移行でき、文書の保存先としても安価なストレージが使える。SaaSへの置き換えも選択肢になる
2. 費用だけを見ると、利点は出にくい。ただし、機器の保守や更新の手間、運用できる人員の確保まで含めて比べる。長期利用の割引（{{ch:cost}}）を使うと差が縮まることもある
3. 現状では向かない。まず契約の条件を確認する。条件の見直しが可能か、国内リージョンに限定すれば認められるかは、顧客と相談する事項
4. 向く。負荷に波があり、集中する時期だけ資源を増やせる

4つのうち、判断が分かれるのは2です。「向かない」と決めつけず、何を比べれば判断できるかを挙げられることが大切です。
:::

:::q 分類 | きっかけを見分ける
次の3社の状況は、本文の「企業がクラウドを選ぶ理由」の6つのうち、どれに当たりますか。複数当てはまる場合はすべて挙げてください。

1. A社：店舗ごとに別々に管理されている売上データを集め、翌朝には全店の傾向を見られるようにしたい
2. B社：本社のサーバールームが被災すると、すべての業務が止まる
3. C社：新機能の提供に半年かかっており、競合に後れを取っている。サーバーの保守期限も2年後に迫っている
:::a
1. データ活用
2. 災害対策（BCP）
3. 開発スピードと、ハードウェアの老朽化・保守切れ

C社のように複数のきっかけが重なる場合は、優先順位を確認します。保守期限に間に合わせることを優先するなら、まず変更の少ない方法で移し、その後で開発の進め方を見直す、という2段階の計画が現実的です。両方を一度に狙うと、期限に間に合わないリスクが高まります。
:::

:::q 記述 | 1分で説明する
あなたの担当するシステム（思いつかなければ、勤務先の勤怠管理システムを想定してください）について、「なぜクラウドに移すのか、あるいは移さないのか」を、役員に1分で説明する文章を書いてください。
:::a
決まった正解はありません。次の点が含まれているかを確認してください。

- 今の課題が、技術の言葉ではなく業務や経営の言葉で述べられている（例：「機器の保守が来年切れる」「月末の処理が遅く、残業が発生している」）
- クラウドに移すことで、その課題がどう解決されるかが述べられている
- 費用と期間の見込みが、前提とともに述べられている
- リスクや、移さない場合の選択肢にも触れている

解答例：「勤怠管理システムのサーバーは、来年9月に保守が切れます。同じ構成で機器を買い替えると約○○万円かかり、5年後にまた同じ更新が必要です。クラウドに移すと、機器の更新がなくなり、月末の集中時だけ処理能力を増やせるため、締め処理の待ち時間も短くできます。移行は6か月、費用は○○万円を見込んでいます。移行中の2週間は新旧を並行して動かし、問題があれば元に戻せるようにします」

「新しい技術だから」は理由になりません。書いた文章を同僚に読んでもらい、質問が出たところを補うと、説明の力がつきます。
:::
