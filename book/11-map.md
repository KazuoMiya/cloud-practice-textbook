第2部では、8つのステップを通じて1つのWebシステムを少しずつ組み上げます。毎回別のものを作るのではなく、前のステップで作ったものに部品を足していくため、部品同士のつながりが理解できます。

{{fig:buildmap|第2部で最終的に作る構成。番号は部品を作るステップ}}

ステップ1〜4で利用者からデータベースまでの通り道を作り、5で異常に気づく仕組み、6でVPCの外のサーバーレスを加えます。最後に7でここまでをコードで作り直し、8で変更を自動で届ける仕組みを作ります。点線は、中から外へ出る通信です。

| ステップ | 作るもの | 身につく力 | 期間の目安 |
|---|---|---|---|
| 1. S3とCLI | IAM、AWS CLI、S3、CloudFront | 権限と操作の基本、公開範囲の考え方 | 1週 |
| 2. ネットワーク | VPC、サブネット、ルートテーブル、IGW、NATゲートウェイ | 通信の通り道を設計して作る | 1〜2週 |
| 3. サーバーと負荷分散 | EC2、ALB、Auto Scaling、Session Manager | 冗長化と自動回復 | 1〜2週 |
| 4. データベース | RDS、DBサブネットグループ、Secrets Manager | データの置き場所と保護 | 1週 |
| 5. 監視と運用 | CloudWatch、CloudTrail、SNS、バックアップ | 異常に気づき、記録を残す | 1週 |
| 6. サーバーレス | API Gateway、Lambda、DynamoDB | サーバーを持たない設計 | 1週 |
| 7. IaC | CloudFormation、AWS CDK、Terraformのいずれか | 同じ環境を何度でも再現する | 1〜2週 |

各ステップは、完成したら一度すべて削除して構いません。次のステップでは、前の構成をもう一度作るところから始めると、それ自体が復習になります。ステップ7でIaCを覚えると、この作り直しが数分でできるようになります。

## 各ステップの章の読み方

第12章から第19章は、どれも同じ構成になっています。

| 節 | 内容 |
|---|---|
| この章のゴール | ステップを終えたときに、説明できるようになること |
| 進め方 | 作るものと順番。細かな操作は公式のハンズオンを併用する |
| つまずきやすい点 | よく出る症状と、原因の見つけ方 |
| 確認ポイント | 自分の言葉で説明できるかを確かめる項目 |
| 実技の合格基準 | 作ったものが正しく動いていることを、コマンドの出力や画面で示す項目。指導役がいる場合は、ここに書いた「提出するもの」で確認を受ける。確認ポイントと合わせて、すべて満たしたら次へ進む |
| わざと壊してみる | 意図的に失敗させ、エラーの出方と直し方を確かめる |
| 片付け | その日のうちに消すものと、消す順番 |
| 本番ではどう変わるか | 学習用の構成と、実際の案件の構成の違い。第3部への橋渡し |
| 章末問題 | 仕組みの理解と、判断の練習 |

「確認ポイント」は説明できるかどうかを、「実技の合格基準」は実際にできているかどうかを確かめます。説明はできるが作れない、作れたが理由を説明できない、のどちらも、案件では通用しません。合格基準のコマンドは、案件で「設定が正しいことを、証拠を付けて報告する」ときにも、そのまま使えます。

作ったものは、文書にも残します。{{ch:docs}}に、パラメータシート、作業手順書、試験項目書のひな形と、この構成での記入例があります。ステップ2からは、作る前にパラメータシートを書き、作った後に実際の値と突き合わせてください。

「わざと壊してみる」は省略しないでください。案件で起きる問題には、ここで体験する失敗と同じ形のものが、数多くあります。エラーの出方を一度見ておくと、本番で同じ表示を見たときに落ち着いて対処できます。

:::tip 作り直しを前提にする
各ステップは、完成したら一度すべて削除してかまいません。費用を抑えられるうえ、作り直すこと自体が復習になります。2回目は手順を見ずに作れるか、3回目は人に説明しながら作れるかを試してください。ステップ7でコード化すると、作り直しは数分で終わるようになります。
:::

## 章末問題

:::q 説明 | 完成した構成の通信を追う
図の構成が完成したとして、次の3つの通信が、それぞれどの部品をどの順に通るかを答えてください。

1. 利用者が、画像などの静的なファイルを取得する
2. 利用者が、データの登録を伴う画面を操作する
3. アプリサーバーが、OSの更新プログラムを外部から取得する
:::a
1. 利用者 → CloudFront → S3。VPCの中は通らない
2. 利用者 → ALB（パブリックサブネット）→ アプリのEC2（プライベートサブネット）→ RDSのプライマリ（DB用のプライベートサブネット）。返事は逆の順に戻る
3. アプリのEC2 → NATゲートウェイ（パブリックサブネット）→ インターネットゲートウェイ → 外部。図の点線の経路

2では、RDSのスタンバイには通常の通信は届きません。スタンバイは、プライマリから複製を受け取り、障害時に切り替わるために待機しています。また、この図ではALBへ直接アクセスする形になっていますが、本番ではCloudFrontをALBの前にも置く構成がよく使われます（{{ch:pattern}}）。
:::

:::q 分類 | 部品と分野、作るステップ
図に出てくる次の部品について、{{ch:parts}}の6分野のどれに当たるかと、何番のステップで作るかを答えてください。

ALB、NATゲートウェイ、RDS、CloudTrail、DynamoDB、ECR
:::a
| 部品 | 分野 | ステップ |
|---|---|---|
| ALB | ネットワーク | 3 |
| NATゲートウェイ | ネットワーク | 2 |
| RDS | データベース | 4 |
| CloudTrail | 監視・運用 | 5 |
| DynamoDB | データベース | 6 |
| ECR | コンピュート（コンテナイメージの置き場） | 8 |

ECRのように、6分野にきれいに収まらない部品もあります。その場合は「何の部品を支えているか」で考えます。ECRは、コンテナを動かすために必要な保管場所なので、コンピュートの周辺として捉えると理解しやすくなります。
:::
